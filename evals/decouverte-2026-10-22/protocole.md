# Essai de découverte depuis le README

Propriétaire : coordinateur de maintenance. Version : 1. Date : 22 octobre 2026. Référence : `8104bacd8872ac040a670ec6413c0c0f82585b16`, skill distribué 0.4.1. Essai exploratoire d'un agent en contexte neuf ; aucun utilisateur humain ni panel représentatif.

## Plan fixé avant lancement

Un seul testeur, lancé avec `fork_turns=none`, reçoit un mandat de parcours et le README comme unique document d'entrée. Il ne reçoit ni la conversation principale, ni les critiques précédentes, ni une liste de défauts attendus. Profil demandé : analyse, `gpt-6.1-sol`, effort `medium`, selon la politique Orka ; paramètres appliqués et consommation inconnus si non exposés.

1. Lire uniquement le README anglais et consigner un premier regard avant toute autre documentation.
2. Poursuivre par les seuls liens explicitement proposés dans les documents déjà consultés. Une traduction accessible par lien est autorisée ; tout accès doit être tracé. La copie publique du dépôt est figée hors du dépôt de travail. Aucun accès aux résultats ou critères de cet essai.
3. Essayer le parcours jusqu'à une installation de démonstration dans un dossier temporaire si les instructions le permettent, puis préparer une première mission. Aucune modification de configuration personnelle, ouverture de chat utilisateur ou mission métier réelle.
4. Conserver journal du parcours, constats et preuves, messages d'erreur utiles, documents consultés et mesures disponibles. Le testeur ne délègue pas. Un seul passage, aucun retour de correction de fond.

Le terme « depuis le README seulement » désigne le seul point d'entrée. Le premier regard isole la lecture sans liens ; le second passage reproduit une navigation documentaire permise. Ne pas confondre un manque dans le README avec un manque résolu par un guide lié.

## Actions et preuves

Lecture locale de la copie figée, lecture de pages publiques liées et téléchargement du ZIP public sont permis. Copie/extraction uniquement dans le dossier temporaire du test. Aucun envoi, compte, dépense, publication, déploiement, exécution des scripts livrés ou lancement d'étude. Une impossibilité découlant de ces limites est une limite du test, pas automatiquement un défaut du README. Le droit de constater un problème ne donne pas celui de le corriger.

Revue du coordinateur après capture : compréhension du produit ; choix d'un hôte et d'un chemin d'installation ; distinction usage courant/Python ; capacité à préparer une première mission ; limites de délégation et preuves ; caractère reproductible des blocages. États : observé, résolu par un lien, non vérifié ou limite du test. Ne pas inventer de score de satisfaction ou de gain.

Avant une correction éventuelle, figer les sorties et leurs empreintes, puis distinguer défaut reproduit, difficulté déclarée, préférence éditoriale et limite d'environnement. Les constats originaux restent distincts de la revue.

## Limites

Contexte de conversation neuf et fichiers séparés, sans sandbox technique empêchant tout autre accès. Les consignes générales et le catalogue de skills de l'hôte peuvent rester visibles. Le testeur ne doit pas charger Orka comme instruction de travail : s'il ouvre le skill via un lien, il l'examine comme contenu du parcours, sans exécuter sa mission d'entreprise. Toute lecture hors périmètre doit être signalée. Ce n'est pas une preuve de découverte automatique du skill dans une nouvelle session Codex, Claude ou Hermes ; un dossier temporaire ne constitue pas un hôte réellement configuré. La lecture de Markdown ne prouve pas le rendu visuel sur tous les navigateurs.

Les durées d'envoi à première observation incluent latence et attente. Modèle/effort appliqués, tokens, coût et temps de calcul moteur restent inconnus sans télémétrie. Aucun ajustement du README n'est autorisé dans cet essai.
